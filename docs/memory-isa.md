## Организация памяти

Процессор построен по гарвардской архитектуре: память команд и память данных физически разделены и имеют собственные шины адреса и данных. Обе памяти однопортовые, адресация в обеих байтовая. Машинное слово — 32 бита (4 байта), слова хранятся в порядке little-endian. Все обращения к памяти выполняются целыми словами по адресам, кратным 4; обращение по невыровненному адресу останавливает моделирование с ошибкой.

Обращения к обеим памятям проходят через кеш: к памяти команд через кеш команд (I-cache), к памяти данных через кеш данных (D-cache). Обращение к кешу занимает 1 такт, к памяти — 10 тактов. Устройство кешей описано в разделе «Модель процессора».

### Регистры

```text
       Регистры, доступные программисту
+---------------------------------------------+
| R0      | результат функции, вспомогательный |
| R1..R7  | временные значения выражений       |
| FP      | указатель кадра функции            |
| SP      | указатель стека                    |
+---------------------------------------------+
| PC      | счётчик команд (неявно)            |
| N Z V C | флаги (неявно)                     |
+---------------------------------------------+
```

Все регистры 32-битные. `R0`–`R7`, `FP` и `SP` могут использоваться как операнды любых команд. `SP` и `FP` — специальные регистры: `SP` неявно используется командами `push`, `pop`, `call`, `ret`, а `FP` по соглашению указывает на кадр текущей функции. `PC` и флаги программист изменяет только косвенно: командами переходов и арифметическими командами соответственно.

Флаги: `N` — результат отрицательный, `Z` — результат равен нулю, `V` — знаковое переполнение, `C` — беззнаковый перенос (для сложения) или заём (для вычитания).

Начальное состояние: `PC = 0`, `SP = 0x10000`, остальные регистры и флаги равны нулю.

Внутренние регистры процессора, недоступные программисту (регистр команды, регистры адреса и данных, микропрограммный счётчик и т.д.), описаны в разделе «Модель процессора».

### Память команд

```text
       Память команд (64 КиБ)
+--------------------------------------+
| 0x0000 : код верхнего уровня         |  <- выполнение начинается здесь
|    ...                               |
|        : halt                        |
|        : функция 1                   |
|    ...                               |
|        : функция 2                   |
|    ...                               |
+--------------------------------------+
```

Программа начинается с адреса `0`. Сначала размещается код операторов верхнего уровня в порядке их записи, после него команда `halt`, затем тела функций в порядке объявления. Поэтому команда перехода на точку входа не нужна. Система прерываний в варианте отсутствует (ввод-вывод `stream`), векторов прерываний нет.

Каждая команда занимает от одного до нескольких 32-битных слов, подряд (см. раздел «Система команд»).

### Память данных

```text
       Память данных (64 КиБ)
+--------------------------------------+
| 0x0000 ... 0x007F : не используется  |  <- адрес 0 никогда не выделяется
| 0x0080            : порт ввода       |
| 0x0084            : порт вывода      |
| 0x0088 ... 0x00FF : не используется  |
+--------------------------------------+
| 0x0100 : глобальная переменная 1     |
| 0x0104 : глобальная переменная 2     |
|    ...                               |
|        : глобальный массив (N слов)  |
|    ...                               |
|        : строковый литерал 1         |
|        :   'h'                       |
|        :   'i'                       |
|        :   0                         |
|        : строковый литерал 2         |
|    ...                               |
+--------------------------------------+
|        свободная память              |
|              ...                     |
|               ^                      |
|               | стек растёт вниз     |
| 0xFFFC : дно стека                   |
+--------------------------------------+
```

#### Порты ввода-вывода (memory-mapped)

Порты ввода-вывода отображены в адресное пространство памяти данных (вариант `mem`). Адреса портов зашиты в модель процессора (hardcode):

- `0x80` — порт ввода. Чтение слова по этому адресу извлекает из потока ввода очередной символ и возвращает его код, дополненный нулями до 32 бит. Если поток ввода исчерпан, моделирование останавливается.
- `0x84` — порт вывода. Запись слова по этому адресу добавляет в поток вывода символ с кодом, равным младшему байту слова.

Специальных команд ввода-вывода нет: к портам обращаются обычные команды с операндом в памяти, например `mov R1, [0x80]` или `mov [0x84], R1`. Обращения к портам идут мимо кеша данных, иначе повторное чтение порта ввода возвращало бы старое значение из кеша.

#### Статические данные

Начиная с адреса `0x100` транслятор размещает статические данные в следующем порядке:

1. Глобальные переменные (по одному слову) в порядке объявления. Сюда же относятся переменные, объявленные внутри блоков кода верхнего уровня: у кода верхнего уровня нет кадра в стеке, поэтому каждая такая переменная получает собственное слово статической памяти.
2. Глобальные массивы (по `N` слов) в порядке объявления.
3. Строковые литералы в порядке появления в тексте программы.

В образе памяти данных переменные и массивы заполнены нулями, а строковые литералы — своими символами. Образ памяти данных создаётся транслятором и загружается в память перед запуском.

#### Стек

Стек расположен в конце памяти данных и растёт в сторону уменьшения адресов. `SP` указывает на последнее записанное слово; первоначально `SP = 0x10000`, поэтому первое значение записывается по адресу `0xFFFC`. Стек хранит кадры функций (аргументы, адрес возврата, сохранённый `FP`, локальные переменные) и временные значения, для которых не хватило регистров. Столкновение стека со статическими данными не проверяется.

### Работа с литералами, константами, переменными и функциями

#### Литералы

Числовые и символьные литералы всегда используются непосредственной адресацией: значение записывается в слово расширения команды (`add R1, #5`, `mov [0x84], #104`). Слово расширения 32-битное, поэтому в него помещается любое значение типа `auto`, и в статическую память числовые литералы никогда не сохраняются.

Строковые литералы всегда сохраняются в статическую память данных. Это единственный вид литералов, занимающий несколько машинных слов. Строка размещается как C-строка (`cstr`): каждый символ в отдельном слове подряд по возрастанию адресов, после последнего символа слово со значением `0`. Литералы располагаются друг за другом без промежутков, одинаковые литералы не объединяются. В коде строковый литерал заменяется непосредственным значением своего адреса: `push #0x0120`.

#### Константы

Константы (`const`) вычисляются при трансляции и подставляются в команды как непосредственные значения. Память под них не выделяется.

#### Переменные

Переменные пользователя всегда хранятся в памяти и никогда не закрепляются за регистрами между операторами. Глобальные переменные и переменные блоков верхнего уровня отображаются на статическую память и адресуются прямой адресацией: `[0x0104]`. Параметры и локальные переменные функций отображаются на кадр в стеке и адресуются относительно `FP`: `[FP+8]`, `[FP-4]`. Так как каждый вызов функции создаёт новый кадр, рекурсия работает без дополнительных механизмов.

Массив занимает `N` слов подряд. Имя массива в выражении — адрес его первого (младшего) слова. Для глобального массива это непосредственное значение (`#0x0110`), для локального — `FP` плюс отрицательное смещение. Элемент `a[i]` находится по адресу `a + 4*i`.

Регистры используются только для временных значений внутри одного оператора (см. ниже).

#### Отображение выражений на регистры и память

Транслятор вычисляет выражение рекурсивным обходом AST. Регистры `R1`–`R7` образуют пул временных регистров, который используется как стек: результат каждого узла помещается в следующий свободный регистр, а после использования регистр освобождается.

Возможности CISC используются так: если операнд является листом дерева (литерал, константа, переменная), он не загружается в регистр, а подставляется в команду напрямую как непосредственное значение или операнд в памяти. Например, `x = a + 5 * b` транслируется так:

```text
mov  R1, #5          ; R1 = 5
mul  R1, [FP-8]      ; R1 = 5 * b       (b — операнд в памяти)
mov  R2, [FP-4]      ; R2 = a
add  R2, R1          ; R2 = a + 5 * b
mov  [0x0100], R2    ; x = R2           (x — глобальная переменная)
```

Если свободные регистры закончились (выражение с вложенностью больше 7), значение левого операнда временно сохраняется в стеке командой `push`. После вычисления правого операнда оно извлекается в `R0`, выполняется операция, и результат переносится обратно в регистр пула.

Сравнения в условиях `if`/`while` транслируются в команду `cmp` и условный переход. Сравнение, значение которого используется как число (`x = a < b`), транслируется в `cmp` и команду установки `slt`/`seq`/... , записывающую `1` или `0`. Ленивые `&&` и `||` транслируются в условные переходы, пропускающие вычисление правого операнда.

Перед вызовом функции внутри выражения занятые временные регистры сохраняются в стеке (`push`), а после возврата восстанавливаются (`pop`). Результат функции переносится из `R0` в регистр пула.

#### Функции

Функции хранятся в памяти команд после кода верхнего уровня. Вызов выполняется по следующему соглашению:

1. Вызывающий код вычисляет аргументы слева направо и помещает их в стек одной командой `push` с переменным числом операндов (первый аргумент записывается первым).
2. Команда `call` помещает в стек адрес возврата и переходит на функцию.
3. Пролог функции сохраняет `FP` и выделяет место под локальные переменные:

    ```text
    push FP
    mov  FP, SP
    sub  SP, #4*L      ; L — число слов локальных переменных и массивов
    ```

4. Функция помещает результат в `R0`. Эпилог восстанавливает стек:

    ```text
    mov  SP, FP
    pop  FP
    ret
    ```

5. Вызывающий код удаляет аргументы из стека: `add SP, #4*n`.

Регистры `R0`–`R7` функция может свободно изменять; сохранять их перед вызовом — обязанность вызывающего кода (caller-saved).

Кадр функции с `n` аргументами:

```text
       старшие адреса
+-------------------------+
| аргумент 1              |  FP + 8 + 4*(n-1)
|   ...                   |
| аргумент n              |  FP + 8
| адрес возврата          |  FP + 4
| сохранённый FP          |  FP + 0   <- FP
| локальная переменная 1  |  FP - 4
|   ...                   |
| временные значения      |           <- SP
+-------------------------+
       младшие адреса
```

Адрес возврата — это адрес в памяти команд, но хранится он в стеке в памяти данных: при гарвардской архитектуре это допустимо, поскольку адрес — просто число.

#### Прерывания

Прерывания в варианте не используются: ввод-вывод выполняется синхронно через порты (`stream`).

## Система команд

### Особенности процессора

Система команд — CISC, двухадресная, типа «регистр-память» (по образцу PDP-11 и VAX). Основные особенности:

- Арифметические и логические команды работают как с регистрами, так и с памятью: оба операнда могут находиться в памяти, например `add [FP-4], #1`.
- Пять режимов адресации, включая косвенную адресацию со смещением.
- Команды переменной длины: от одного до нескольких машинных слов. Выборка команды явно читает каждое следующее слово из памяти команд и увеличивает `PC` на 4.
- Команды `push` и `pop` принимают переменное число операндов (от 1 до 255).
- Специальные регистры `SP` и `FP`; `SP` неявно используется командами работы со стеком и вызова функций.
- Устройство управления микропрограммное: каждая команда выполняется последовательностью микрокоманд.

Тип данных один — 32-битное целое. Знаковые операции (сравнения, деление) трактуют его как число в дополнительном коде. Устройство памяти, регистров и ввода-вывода описано в разделе «Организация памяти».

Поток управления: команды выполняются последовательно, `PC` увеличивается на длину команды. Порядок изменяют команды переходов, `call` и `ret`. Команда `halt` останавливает процессор. Прерываний нет.

### Режимы адресации

| Код | Запись        | Значение операнда                    | Слов расширения |
|-----|---------------|--------------------------------------|-----------------|
| 0   | —             | операнд отсутствует                  | 0               |
| 1   | `Rn`          | содержимое регистра                  | 0               |
| 2   | `#value`      | непосредственное значение            | 1               |
| 3   | `[addr]`      | слово памяти данных по адресу `addr` | 1               |
| 4   | `[Rn]`        | слово памяти по адресу из регистра   | 0               |
| 5   | `[Rn+off]`    | слово памяти по адресу `Rn + off`    | 1               |

Коды регистров: `0`–`7` — `R0`–`R7`, `8` — `FP`, `9` — `SP`. Смещение `off` — 32-битное знаковое число, запись `[FP-8]` означает `off = -8`.

Операнд-приёмник (тот, в который пишется результат) не может использоваться в режиме `#value`.

### Кодирование команд

Первое слово команды:

```text
 31        24 23    20 19    16 15    12 11     8 7          0
+------------+--------+--------+--------+--------+------------+
|   opcode   |   M1   |   R1   |   M2   |   R2   |     N      |
+------------+--------+--------+--------+--------+------------+
```

- `opcode` (8 бит) — код операции.
- `M1`, `R1` — режим адресации и регистр первого операнда.
- `M2`, `R2` — режим адресации и регистр второго операнда.
- `N` — число операндов команд `push`/`pop`, для остальных команд `0`.

Неиспользуемые поля равны нулю. Одноадресные команды используют поле первого операнда. За первым словом следуют слова расширения: сначала для первого операнда (если его режим требует), затем для второго.

Команды `push` и `pop` с переменным числом операндов кодируются иначе: в первом слове заполнены только `opcode` и `N`, а за ним идут `N` операндов. Каждый операнд — это слово-описатель, за которым, если нужно, следует слово расширения:

```text
 31    28 27    24 23                                          0
+--------+--------+---------------------------------------------+
|  mode  |  reg   |                      0                      |
+--------+--------+---------------------------------------------+
```

Примеры кодирования (длина в словах — 1, 2, 3 и 6):

```text
add  R1, R2          10111100                      1 слово
add  R1, #5          10112000 00000005             2 слова
mov  [0x84], #104    01302000 00000084 00000068    3 слова
push R1, #5, [FP-8]  02000003                      6 слов
                     11000000                      ; R1
                     20000000 00000005             ; #5
                     58000000 FFFFFFF8             ; [FP-8]
```

### Набор команд

`dst` — первый операнд (приёмник), `src` — второй операнд (источник), `op` — единственный операнд.

#### Пересылка данных и стек

| Код  | Мнемоника              | Действие                                  | Флаги |
|------|------------------------|-------------------------------------------|-------|
| 0x01 | `mov dst, src`         | `dst ← src`                               | —     |
| 0x02 | `push op1, ..., opN`   | для каждого `opi` по порядку: `SP ← SP-4; mem[SP] ← opi` | — |
| 0x03 | `pop op1, ..., opN`    | для каждого `opi` по порядку: `opi ← mem[SP]; SP ← SP+4` | — |

#### Арифметика и логика

| Код  | Мнемоника        | Действие                          | Флаги          |
|------|------------------|-----------------------------------|----------------|
| 0x10 | `add dst, src`   | `dst ← dst + src`                 | N Z V C        |
| 0x11 | `sub dst, src`   | `dst ← dst - src`                 | N Z V C        |
| 0x12 | `mul dst, src`   | `dst ← dst * src` (младшие 32 бита) | N Z, V=C=0   |
| 0x13 | `div dst, src`   | `dst ← dst / src` (к нулю)        | N Z, V=C=0     |
| 0x14 | `rem dst, src`   | `dst ← dst % src` (знак делимого) | N Z, V=C=0     |
| 0x15 | `and dst, src`   | `dst ← dst & src`                 | N Z, V=C=0     |
| 0x16 | `or dst, src`    | `dst ← dst \| src`                | N Z, V=C=0     |
| 0x17 | `adc dst, src`   | `dst ← dst + src + C`             | N Z V C        |
| 0x18 | `sbc dst, src`   | `dst ← dst - src - C`             | N Z V C        |
| 0x19 | `cmp dst, src`   | вычисляет `dst - src`, результат не сохраняет | N Z V C |
| 0x1A | `neg op`         | `op ← -op`                        | N Z V C        |
| 0x1B | `not op`         | `op ← ~op` (побитовое НЕ)         | N Z, V=C=0     |

Деление на ноль (`div`, `rem`) останавливает моделирование с ошибкой. Команды `adc` и `sbc` используются для арифметики двойной точности: сложение 64-битных чисел выполняется как `add` младших слов и `adc` старших.

#### Переходы

Операнд `op` — адрес перехода в памяти команд, обычно непосредственное значение (метка): `jmp #loop`. Условие проверяется по флагам, выставленным предыдущей командой `cmp` (или арифметической командой).

| Код  | Мнемоника | Условие перехода         | Смысл после `cmp a, b` |
|------|-----------|--------------------------|------------------------|
| 0x20 | `jmp op`  | всегда                   |                        |
| 0x21 | `jeq op`  | `Z = 1`                  | `a == b`               |
| 0x22 | `jne op`  | `Z = 0`                  | `a != b`               |
| 0x23 | `jlt op`  | `N ≠ V`                  | `a < b` (знаковое)     |
| 0x24 | `jle op`  | `Z = 1` или `N ≠ V`      | `a <= b`               |
| 0x25 | `jgt op`  | `Z = 0` и `N = V`        | `a > b`                |
| 0x26 | `jge op`  | `N = V`                  | `a >= b`               |
| 0x27 | `jcs op`  | `C = 1`                  | беззнаковое `a < b`, перенос |
| 0x28 | `jcc op`  | `C = 0`                  | беззнаковое `a >= b`   |

#### Установка по условию

Записывают в `op` значение `1`, если условие выполнено, иначе `0`. Условия те же, что у переходов. Используются для сравнений и `!`, значение которых нужно как число.

| Код  | Мнемоника | Условие            |
|------|-----------|--------------------|
| 0x31 | `seq op`  | `Z = 1`            |
| 0x32 | `sne op`  | `Z = 0`            |
| 0x33 | `slt op`  | `N ≠ V`            |
| 0x34 | `sle op`  | `Z = 1` или `N ≠ V`|
| 0x35 | `sgt op`  | `Z = 0` и `N = V`  |
| 0x36 | `sge op`  | `N = V`            |

Младшие четыре бита опкодов команд установки совпадают с младшими битами соответствующих команд переходов (`seq` — `0x31`, `jeq` — `0x21`), поэтому условие для обеих групп вычисляет один и тот же блок процессора.

#### Вызов функций и останов

| Код  | Мнемоника  | Действие                                        |
|------|------------|-------------------------------------------------|
| 0x40 | `call op`  | `SP ← SP-4; mem[SP] ← PC; PC ← op` (`PC` уже указывает на следующую команду) |
| 0x41 | `ret`      | `PC ← mem[SP]; SP ← SP+4`                       |
| 0x00 | `halt`     | останов процессора                              |

Код `halt` равен нулю, поэтому переход на незаполненную память команд останавливает процессор.

### Количество тактов

Количество тактов каждой команды определяется её микропрограммой и приведено в разделе «Модель процессора» (подраздел «Количество тактов»). Кратко: `T = 2 + T1 + T2 + Tвып`, где 2 такта занимают выборка первого слова и декодирование, `T1` и `T2` зависят от режимов адресации операндов, а `Tвып` — от команды. Например, `add R1, R2` выполняется за 6 тактов, `add [FP-4], #1` — за 10. Каждый промах кеша добавляет 9 тактов ожидания (19 при вытеснении изменённой строки D-cache).

### Пример: функция `collatz_length` в машинном коде

Ниже код, записанный вручную, чтобы показать использование возможностей системы команд: арифметику прямо над переменными в памяти и адресацию относительно `FP`. Параметр `n` находится в `[FP+8]`, локальная переменная `steps` — в `[FP-4]`.

```text
collatz_length:
    push FP                 ; пролог
    mov  FP, SP
    sub  SP, #4             ; место под steps
    cmp  [FP+8], #0         ; if (n <= 0)
    jgt  #pos
    mov  R0, #-1            ;     return -1
    jmp  #exit
pos:
    mov  [FP-4], #0         ; auto steps = 0
loop:
    cmp  [FP+8], #1         ; while (n != 1)
    jeq  #done
    mov  R1, [FP+8]         ;     if (n % 2 == 0)
    rem  R1, #2
    cmp  R1, #0
    jne  #odd
    div  [FP+8], #2         ;         n = n / 2
    jmp  #next
odd:
    mul  [FP+8], #3         ;         n = 3 * n + 1
    add  [FP+8], #1
next:
    add  [FP-4], #1         ;     steps = steps + 1
    jmp  #loop
done:
    mov  R0, [FP-4]         ; return steps
exit:
    mov  SP, FP             ; эпилог
    pop  FP
    ret
```

Вызов из кода верхнего уровня, например `r = collatz_length(6);`:

```text
    push #6                 ; аргумент
    call #collatz_length
    add  SP, #4             ; убрать аргумент
    mov  [0x0100], R0       ; r = результат
```

### Формат машинного кода

Транслятор создаёт один бинарный файл:

| Смещение | Размер      | Содержимое                                  |
|----------|-------------|---------------------------------------------|
| 0        | 4 байта     | сигнатура `LAB4`                            |
| 4        | 4 байта     | размер образа памяти команд в байтах        |
| 8        | 4 байта     | размер образа памяти данных в байтах        |
| 12       | —           | образ памяти команд (загружается с адреса 0) |
| —        | —           | образ памяти данных (загружается с адреса 0) |

Числа в заголовке и слова в образах записаны в порядке little-endian.

Дополнительно транслятор создаёт текстовый листинг. Каждая команда занимает одну строку: адрес, все слова команды в шестнадцатеричном виде, мнемоника. Отдельно выводится содержимое памяти данных:

```text
; instruction memory
0000 - 01302000 00000084 00000068 - mov [0x84], #104
000C - 00000000 - halt

; data memory
0100 - 00000068 - 'h'
0104 - 00000069 - 'i'
0108 - 00000000 - '\0'
```
